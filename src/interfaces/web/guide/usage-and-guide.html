UI/UX App Designer

Usage and guide for the path, icon, button, element, screen and workflow designers.

Usage and guide

Getting started

Everything you design is stored in a SQLite database and can be exported to SVG (with animation) and to working HTML / CSS / TS / JS.

The hierarchy

Each level is built from the one before it. The designers follow the same order:

Path→Icon→Button→Element→Screen→Workflow
LevelWhat it isCan contain
PathA reusable group of vector shapes on a 24×24 gridshapes, other path groups
Icon24×24 compositionpath groups, own shapes
ButtonThemed frame with an icon, optionally a popup or rotating menuicons, paths, shapes
ElementUI building block: HTML elements, forms, cards, navbars…shapes, icons, buttons, other elements
ScreenA device-sized compositionicons, buttons, elements
WorkflowScreens placed on a canvas and linked togetherscreens

If you drop something into a level that cannot hold it, you get a hint and nothing happens. An element can never contain itself.

The window

  • Top bar: menus (Design, Edit, Path, View, Theme, Export, Help), the Screen designer / Workflow designer switch, and the theme selector.
  • Left panel: the libraries Paths · Icons · Buttons · Elements, the Screens catalog and the Workflows. Drag the divider to resize it, double-click it to collapse.
  • Right panel: the designer of whatever you opened, with its toolbar, canvas and inspector.
  • Status bar: the pointer position and the totals of your library.

Using the libraries

  • Search and the category chips filter every library.
  • Hover a cell for its toolbar: ✎ edit, ⧉ clone, ⤓ export SVG, 🗑 delete.
  • Click a cell to open it in its own designer. Drag it onto the open designer, or double-click it, to place it.
  • Cells that the open designer cannot accept are dimmed.
  • + New … creates a path, icon, button, element or screen. Import SVG turns any SVG file into a path group, icon or element.
Every design has a variable name (dashed words, unique, used in code), a label (shown to users) and a description-dev (instructions for the dev team and their coding agents). Fill them in; they are exported to DEV-NOTES.md.

Every change is written to the database the moment you make it, and can be undone with Ctrl+Z. Save marks a version you are happy with; Reset goes back to it (see Save, Save as, Reset and Back).

Save, Save as, Reset and Back

The bar at the very top of every designer (paths, icons, buttons, elements, screens and workflows) keeps track of your edits.

ButtonWhat it does
← BackReturns to the page you had open before (Alt+← or the browser's Back button do the same). Its tooltip names that page. It is greyed out on the first page.
💾 Save Ctrl+SMarks the current version as the saved one. It blinks while there are changes you have not saved. Next to it you read Unsaved changes or All changes saved.
Save as…Stores the current version, including your unsaved changes, as a new design under a name you type, and opens it. The original goes back to the version it had at its last save.
↺ ResetThrows away every change since the last save (asks first). Greyed out when there is nothing to throw away.

Good to know

  • Changing something back by hand (or with undo) until it equals the saved version makes the blinking stop by itself.
  • Leaving with unsaved changes (opening another design, pressing Back, closing a designer dialog, closing the browser tab) asks: Save, Discard changes (back to the last save) or Cancel.
  • Changes are never lost by accident. Edits are already in the database when you make them, so a crash or a reloaded page keeps your work as it was. The page then treats that state as saved, so the safety net of Reset is only there while the design stays open.
  • Workflows have the same bar: moving screens, adding or editing links and changing the name or description-dev count as edits.
  • Designers opened in a dialog (the ✎ on a screen in the Workflow designer) have Save, Save as and Reset too; they have a Close button instead of Back.
  • The Design menu lists the same commands.

Further toolbar buttons: undo, redo, duplicate, delete, bring to front, send to back, zoom, and the switches Grid (show grid), Snap grid, Snap 9-pt and Animate (play animations on the canvas).

Snapping

  • Snap grid uses the grid of the open designer: 1 for paths and icons, 4 for buttons, 8 for elements, 24 for screens (changeable under View → Grid size).
  • Snap 9-pt snaps to the nine reference points of the design's box: corners, edge centres and the centre. Pink guides show what you snapped to.
  • In the inspector, the 3×3 button grid places the selection on one of those nine points.

Inspector

  • Design: name, variable name, label, category, size, description-dev.
  • Layers: every node of the design in z-order, with 👁 show/hide and 🔒 lock. Click one to select it.
  • Selected node: variable name, surface role, rotation, position and size, fill, stroke, line size × global, opacity, corner radius, all attributes as JSON, and animations.
Line sizes are stored as a ratio of the theme's global line size, never a fixed number. Change the theme's line size once and every icon follows.

Path designer

Draw and edit reusable vector shapes. Icons are built from path groups, so editing one updates every icon that uses it.

Create a path group

  1. Open the Paths tab and click + New path, or Import SVG to bring in an SVG file.
  2. Draw with the rectangle, circle, line or pen tools, or edit the starter shape.
  3. Name it, give it a category and write its description-dev in the inspector.

Vertex editing

  1. Select a path and press Enter (or N, or double-click it, or Edit vertices in the inspector). Rectangles, circles and lines are converted to a path first.
  2. Drag vertices (squares) and bezier handles (pink dots). Drags snap to the grid; hold Ctrl for free movement.
  3. Press Esc, Enter or Done to leave vertex mode.

Pen tool — draw bezier curves

  • Click for a corner point; click and drag for a smooth point, the handles follow the drag.
  • Click the first point (it turns green) to close the path. Enter, a double-click or a right-click finishes an open path.
  • Backspace removes the last point, Esc cancels.

Pathfinder, crop and group

These work on paths, rectangles, circles, ellipses, lines and polygons. Select the shapes first.

⊻ Excludeeverything except the overlap

The result of Cut out, Crop and Union is made of straight segments (curves are flattened). Use Simplify afterwards to reduce the vertices.

Right-click a shape for a menu with all of these (its first entry, Open editor, opens whatever editor fits the element). Paths can also be nested: place one path group inside another with a double-click or a drag.

Icon designer

An icon is a 24×24 composition of path groups, drawn with the theme's gradient stroke.

  1. Open the Icons tab and click + New icon (or open an existing icon).
  2. Switch to the Paths tab and drag path groups onto the canvas, or double-click them. They fill the 24×24 grid and can then be moved, resized and rotated.
  3. Rectangles, circles, lines and the pen also work here for one-off shapes.
  4. Double-click a placed path (or use Open editor in the inspector) to edit that path group itself. All icons that use it change.

Style and animation

  • The stroke, glow and line size come from the theme. Set a different line size per shape with Line size × global (a ratio).
  • Select a shape and use + Add animation…: move, rotate, scale, fade, visible, blink, pulse, bounce, draw and glow, with duration, delay, easing, repeat, direction and trigger (load / hover / click). Animate in the toolbar previews them.
  • Animations are exported inside the SVG file as CSS keyframes.
Click a cell in the Icons tab to open it; the ⤓ button downloads that icon as an SVG including its animation.

Button designer

A button is a themed frame with an icon. It can also own a popup menu or a rotating radial menu with nested sub items.

Build a button

  1. Open the Buttons tab and click + New button (or start from a ready-made one).
  2. Drag an icon from the Icons tab into the frame. It is centred at 62.5% of the button, the same ratio the app uses everywhere.
  3. Change the size with the box handles or the W/H fields. Scale contents (toolbar) makes the frame and icon scale together.

Add a menu

In the inspector, open the Menu section.

SettingMeaning
Menu typepopup: opens in place · rotating: the clicked item's icon replaces the centre and its sub items are shown
Layoutfan (radius, start angle, sweep) or list (direction up / down / left / right, gap)
Item sizeas a ratio of the button size, so the menu scales with the button
Centre icon turnsdegrees the centre icon rotates while open (0 = off)

Add, edit and delete menu items

  1. The canvas shows the menu open. Hover the button or any item to get a small toolbar: ＋ add a sub item · ✎ edit · ← → change the order · 🗑 delete.
  2. Click an item that has sub items to step into its level (its icon appears in the centre). Click the centre to go back one level.
  3. The item dialog sets the label, variable name, icon (picker), an action / event name for leaf items, a target screen and the description-dev.
  4. The same can be done in the inspector: ＋ next to an item adds a sub item, ＋ Add menu item adds a top-level one. Menus can be nested up to six levels.

How the menu behaves

  1. Click the button: the items open.
  2. Click it again: they close.
  3. Click an item with sub items: (rotating) its icon replaces the centre and its sub items are displayed.
  4. Click the centre again: the menu goes one level back.
  5. Click an item without sub items: its action runs (or it navigates to its target screen) and the menu closes.

Switch on Test menu in the toolbar to try exactly this on the canvas. Switch it off to edit again.

The menu belongs to the button. A button placed in an element or on a screen shows the same menu, and a change here applies everywhere that button is used. To get an independent menu, clone the button (⧉ in the Buttons tab). In the element and screen designers a menu stays closed; try it with Test menu here or in an exported page.

Element designer

Elements are UI building blocks: the basic HTML elements, forms, cards, navigation bars and more, built from shapes, icons, buttons and other elements.

Create an element

  1. Open the Elements tab and click + New element.
  2. Pick a preset (buttons, inputs, select, checkbox, radio, switch, slider, headings, lists, table, card, modal, alerts, tabs, breadcrumb, pagination, toolbars, radial and popup menu buttons…) or start from a blank bounding box.
  3. Name it. A copy of the preset is created for you; the presets themselves stay untouched.

The bounding box

  • Every element starts as a box (dashed). Everything you add is placed inside it.
  • With nothing selected, drag the box handles on the right, bottom or corner to resize it. All sub items resize with it. Turn off Scale contents to resize the frame alone.
  • You can also type the width and height in the inspector. The same scaling applies when you resize a placed instance on a screen.

Fill it

  • Drag icons, buttons and other elements in from the libraries. Draw shapes and add text with the toolbar.
  • Give shapes a surface role (card, button, field) so they take the look of the active theme.
  • Set the HTML element (button, input, div…) in the inspector. The export uses it so the dev team knows the semantic tag.
  • Write the description-dev: props, states, behaviour.
Double-click a placed button or icon to open it in its own designer, then use ← Back to return to the screen.

Screen designer

A screen is a device-sized composition of icons, buttons and elements.

  1. Open the Screens tab and click + New screen. Choose a name and a device (iPhone, Android, tablet, web, watch). The device size can be changed later in the inspector.
  2. Drag elements, buttons and icons from the libraries onto the device. Drop position and size are snapped to the grid.
  3. Use Snap 9-pt and the 3×3 placement grid to pin items to the top, bottom, left, right or centre of the screen.
  4. Resize placed elements with their handles; their content scales with them.
  5. Write a name, label and description-dev for the screen, and give important items a variable name and a description-dev too.

Themes

Switch the theme in the top bar at any time. The same screen is shown as Liquid glass, Glow lines or Neumorphic light / dark.

The catalog

  • Tick screens for export, or use Select all, None and Invert. The search and the category chips narrow the list first.
  • Export selected… and Export all… open the export dialog (see Export).
Items you place on a screen are links to the library: edit an element, button or icon and every screen that uses it updates.

Open editor

Every element on the canvas has an ✎ Open editor button at the top of the inspector, and the same entry at the top of the right-click menu (double-click does it too). What it opens depends on the element:

ElementOpen editor does
a placed icon, button, element or path groupopens it in its own designer (← Back brings you back)
textlets you edit the words
a groupenters the group: selects the items inside it
a rectangle, circle, line or pathstarts vertex editing

Click actions

Select an element and use the Click action section of the inspector to say what happens when the user clicks or taps it in the finished app:

ActionResult in the exported page
Route to a screenthe element becomes a link to that screen's page
Open an element as a popupthe chosen element opens in a dialog over the page
Open an element as a drawerthe element slides in from the left, right, top or bottom
Go backreturns to the previous page
  • Popups and drawers close with the ✕, a click on the backdrop or Esc. Build the content once as an element (a menu, a filter sheet, a confirmation…), then open it from as many screens as you like.
  • Turn on Test actions in the toolbar to try the actions on the canvas. Routes open the target screen, popups and drawers appear over the canvas. Turn it off to edit again.
  • Elements with an action show a ⚡ badge in the Layers list. The action sits on the element you click; if it is inside a group, put it on the group.
  • Routes are also available as links in the Workflow designer. If both exist on the same element the page gets one clickable area, not two.
  • If the element or screen that an action points to is deleted later, that action is left out of the export.
  • The actions are exported in data/manifest.json, ts/screens.ts and DEV-NOTES.md too. The element's description-dev is carried along for the dev team.

Workflow designer

See all your screens on an infinite canvas and describe how the user moves between them.

  1. Open the Workflows tab and click + New workflow, or open one. Switch to the workflow designer with the top-bar tab.
  2. Add screens with + Add screen… or Add all screens. Auto layout arranges them left to right along the links.
  3. Drag a screen by its header to move it. ▾ / ▸ collapses and expands it, ✎ opens the screen in a modal screen designer, ✕ removes it from this workflow.
  4. Switch on 🔗 Link tool, then drag from a button or text on one screen to another screen. The link remembers the element that triggers it.
  5. When you let go on the target screen a form asks for the link's name and description-dev (what happens on this transition: conditions, data passed along, animation…), the gesture and the line style. Cancel creates nothing.
  6. Double-click a link to open the same form again. Changing the Goes to screen in the inspector opens it as well, so you can update the description while you change the screen. Hover a link to read its description.
  7. The inspector also lists the trigger element, target screen, curved or cornered line style and the gesture (tap, long-press, swipe…). Cornered lines hop over each other where they cross.

Pan with Space+drag or the empty canvas, zoom with the wheel. The workflow's own name and description-dev are in the inspector, together with the list of its links.

Export workflow screens… opens the export dialog with exactly the screens of this workflow selected. The links become clickable areas and navigation in the exported pages.

Themes and surface roles

One stored design renders in every theme. Four are built in: Liquid glass, Glow lines, Neumorphic light and Neumorphic dark.

  • Choose a theme in the top bar or the Theme menu. The canvas, thumbnails and exports follow it.
  • Theme → Edit themes…: change colours, the global line size, button size and margin, clone a theme to make your own, or edit its surface roles.
  • Colours in a design are tokens such as {{accent}} or {{text}}, not fixed values, so they change with the theme.

What a surface role is

A surface role tells the theme how to paint a shape (fill, border, shadow), so the same shape looks right in all four themes.

RoleUse it forLook
cardpanels, cards, sheetsglass gradient with a shadow · glowing outline · raised
buttonround or pill button framesglass bubble · glowing outline · small raised bump
fieldinputs, tab bars, trackstranslucent glass · thin outline · inset (pressed in)
shinehighlight on glass buttonsshown in Liquid, hidden in Glow and Neumorphic
bg / bg-glowscreen background, soft glowtheme background; the glow only in Liquid
(none)everything elsekeeps its own fill and stroke
If you set a fill or stroke on a shape that has a role, your colour wins over the theme. Remove it to give control back to the theme.

Animations

Any shape, icon, button or element part can be animated. Animations are stored in the database and exported as CSS keyframes inside the SVG.

  1. Select a shape or placed item.
  2. In the inspector, choose + Add animation… and a type.
  3. Edit its parameters, then press Animate in the toolbar to watch it.
TypeDoes
move / rotate / scalefrom → to values (scale can be one axis, with an origin)
fade / visible / blinkopacity changes
pulse / bouncebreathing scale, bouncing dots
drawdraws the outline of a path
glowpulsing glow
keyframesyour own frames as JSON

Every animation has duration, delay, easing, repeat, direction and a trigger: on load, on hover or on click.

Export

One design as an SVG file

Click ⤓ on a library cell, or use Export → Export open design as SVG. Animations are included. A button is exported with its menu.

A working project (HTML, CSS, TS, JS and SVG)

  1. In the Screens tab tick the screens you want (or use Select all / None / Invert) and click Export selected…. The workflow designer has Export workflow screens….
  2. Choose the themes to include (the exported page can switch between them), which icons to include, and a project title.
  3. Choose the export folder: type an absolute path, or use Browse… in Chrome or Edge.
  4. Press Export.
FileContent

css/, js/, ts/theme variables, page layout, theme switcher, menu runtime and a typed registry (npx tsc -p tsconfig.json compiles the TS)
svg/screens per theme, icons, buttons, elements and an icon sprite

From a terminal: npm run export -- --out C:\folder --themes liquid,glow --screens all. Double-click index.html to open the result; no server is needed.

Tips and troubleshooting

  • I cannot drop an item. The hierarchy decides what fits where. Dimmed cells in the library cannot go into the open designer. A path goes into icons, an icon into buttons, a button into elements, an element into screens.
  • The menu of my button does not open on the screen. Menus are interactive only in the Button designer's Test menu and in exported pages.
  • Vertex editing says the shape is rotated. Select the path and click Apply transform to points, or set Rotation to 0.
  • Cut out says the shapes do not overlap. The result would be empty. Check which shape is on top (Bring to front).
  • My colours do not change with the theme. The shape has a fixed fill or stroke. Clear it, or use a token such as {{accent}}, or give the shape a surface role.
  • Starting over. npm run reset restores the built-in library from the v1 files; your own designs are kept.
  • Where is my data? In data/designer.db (SQLite). Copy that file to back everything up.
